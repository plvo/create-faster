## What create-faster adds

Portless wraps your dev commands so each app is accessible via a named HTTPS domain instead of `http://localhost:3000`.

**Script transformations:**

| Script | Before | After |
|--------|--------|-------|
| `dev` | `{framework dev command}` | `portless run {framework dev command}` |
| `start:portless` | *(new)* | `portless run {framework start command}` |

For example, a Next.js app's `dev` becomes `portless run next dev`, and a Hono app's becomes `portless run bun run --hot src/index.ts`.

Wrangler reads no port variable, so a Hono app on the [Cloudflare](/docs/deployment/cloudflare) deployment runs `wrangler dev` from an `sh -c` that expands `PORT` itself: its `dev` becomes `portless run sh -c 'wrangler dev --port=${PORT:-3000} --persist-to ./.wrangler "$@"' sh`, and the Worker listens on the port portless assigns.

- `dev` is wrapped in place — portless auto-detects the domain from the project context
- `start` is left untouched (production use), a separate `start:portless` script is added for local testing
- `--port` flags are stripped automatically since portless manages port assignment via the `PORT` environment variable: portless sets `PORT` itself for the app, so a `PORT` exported in your shell has no effect on `dev` and `start:portless`. Set `PORTLESS_APP_PORT` to pin the port of the app
- Leading environment assignments stay in front of `portless`: a Hono or Node app's `start:portless` is `NODE_ENV=production portless run bun run src/index.ts`. portless quotes every argument it runs, so `portless run NODE_ENV=production bun ...` would try to execute `NODE_ENV=production` as a command; portless passes its own environment down to the app, so the assignment still applies

**Environment variables:**

When portless is selected, the `{{appUrl}}` placeholder in `.env.example` resolves to the portless domain:

| Context | URL |
|---------|-----|
| Single repo (`myapp`) | `https://myapp.localhost:1355` |
| Turborepo app (`web`) | `https://web.localhost:1355` |

Without portless, `{{appUrl}}` resolves to `http://localhost:{port}`.

**Dependencies:**

- `portless` `^0.15.6` (dev)

**Turborepo mode:**

- `portless` is added as a devDependency to the root **and** each app's `package.json` (so the binary is available on each workspace's PATH)
- Each app gets its own portless-wrapped `dev` script using `portless run` auto-detection
