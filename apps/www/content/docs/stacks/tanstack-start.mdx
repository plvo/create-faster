## What create-faster adds

Beyond the official setup, we include:

**Project Structure:**
- File-based routing with `__root.tsx` layout
- Pre-styled landing page with dark theme
- Router configuration with scroll restoration

**Development Scripts:**
- `dev` - Development server with dynamic port assignment (3000 or turborepo-specific)
- `build` - Production build, emits the Nitro server to `.output/`
- `preview` - Preview the production build
- `postinstall` - Generates `src/routeTree.gen.ts` with `tsr generate` (`@tanstack/router-cli`), so `tsc` and the editor work right after install. `dev` and `build` keep the file up to date, and it is meant to be committed
- `start` - Production server (`node --env-file-if-exists=.env --env-file=.env.start .output/server/index.mjs`): loads the app's `.env` when it exists (otherwise Node prints `.env not found. Continuing without it.` on stderr), then `.env.start` (`NODE_ENV=production` and the app's `PORT`), and listens on the app's port. When `start` runs from the app directory, a `PORT` or `NITRO_PORT` exported in the shell overrides it; in Turborepo, `turbo start` from the root runs in strict env mode and drops shell variables other than `PORT`, so only the two files apply to the others

**Vite Configuration:**
- TanStack Router DevTools enabled (a panel of the [TanStack Devtools](/docs/modules/data-fetching/tanstack-devtools) shell when that module is selected)
- Nitro (`nitro/vite`) as the production server: the build emits `.output/server/index.mjs`, which `start` runs. The [Cloudflare Workers](/docs/deployment/cloudflare) and [Cloudflare Workers (static)](/docs/deployment/cloudflare-static) deployments replace it
- Tailwind CSS v4 via Vite plugin
- TypeScript path aliases through Vite's native `resolve.tsconfigPaths`

**Styling:**
- Tailwind CSS v4 (latest version using new Vite plugin)
- Dark theme with slate color palette
- Geist Sans and Geist Mono, loaded from `@fontsource-variable/geist` and `@fontsource-variable/geist-mono`

Files created:
```
src/
├── components/
│   └── not-found.tsx      # Root notFoundComponent
├── routes/
│   ├── ___root.tsx        # Root layout with meta tags and styles
│   └── index.tsx          # Home page with welcome content
├── router.tsx             # Router instance with scroll restoration
└── styles.css             # Global styles with Tailwind import

vite.config.ts             # Vite config with all plugins
.env.start                 # NODE_ENV=production and the default PORT for `start` (both win over .env): port 3000, or the app's own port in Turborepo
tsconfig.json              # TypeScript config with path aliases
```

**Integration notes:**
- ORM integration: When Drizzle or Prisma is selected, database scripts are added to `package.json`
- Turborepo: Uses `@repo/db` package for shared database logic
- Single repo: Includes database scripts directly in app package
- Build output: `.output/` is added to `.gitignore`, and in Turborepo it is part of the `build` task outputs so cached builds keep a runnable server
